# 识海深潜关卡内自动运行

关卡内自动运行已接入；完整流程仍需独立实机验收。

## 使用入口

在 GUI 的识海深潜面板选择“关卡内自动运行”。从稳定的玩家棋盘或位面间隙启动。独立回合安全上限默认为 100，可设 1–100。复用现有取消按钮。

运行识海深潜任务前，在 GUI 设置中启用并保存「使用桥接输入器」。命令行使用 `resonance_pc.input.mode: bridge`。移动和层转规划按桥接快照报告的阶数使用三阶、四阶或五阶规则。旧的拖动和扫描路线参数继续接受，棋盘读取统一走桥接快照。

任务为 `consciousness_deep_dive_planned_run_pc`，采用 `initialize → advance → finish`。可设置扫描预算。实时规划预算默认 350 毫秒，也以 350 毫秒为上限。自动运行统一使用 `encounter_then_inspiration`，旧调用传入的 `chase` 或 `inspiration` 也会按这个目标运行。

最后一回合预测遭遇率为零时，仍执行可用操作并等待奇点行动。若奇点撞上来，继续处理 Boss 战。胜负以客户端最终结算状态为准。

位面间隙默认依次执行复苏、推力强化、觉醒升构和招募。设置允许调整顺序、启用状态和单次间隙的次数上限。默认只强化推荐推力且按价格升序，集中升觉且目标最高 5 级，招募按乘员等级升序。尘埃不足时结束本次间隙的付费操作。

候补补员在战前编队按稀有度补齐。启用「一队打到死」时，完整循环以首次确认的出战队伍为固定阵容。单独从已有局发送任务时，以任务首次确认的编队或进入间隙时的五人存档编队为准。无法恢复固定阵容或凑齐五人时，使用游戏的「结束下潜」。客户端最终结算状态连续两次确认后，关卡内任务停在结算页，完整循环收尾后继续。缺员结算是否计数取决于「失败局是否记录」。

「每场最多重打次数」默认 0。设为正整数后，在已确认的识海战败页通过原生「重打」和确认框再次进入同一场战斗。每个战斗事件分别计数。额度用尽或游戏未开放重打入口时进入原有结算流程。

商店默认按低价优先购买推荐商品。可调整排序、关闭购买或设置每次进店的购买上限。事件可按名称调整选项优先级和禁用选项。

## 已接入的循环

1. 每个新玩家回合从桥接器读取一份完整棋盘快照，核对玩家、奇点、灵感和六个面的全部节点。
2. `plan_current_state` 使用当前棋盘和真实剩余回合、移动及层转额度。求解器先比较期限内碰上奇点的概率，概率相同时比较成功相遇分支的灵感期望。战斗胜负独立于路线评分。旧坐标和旧方案随重新读取失效。
3. 桥接器调用客户端的移动和层转界面处理函数。移动从客户端可移动格列表中按原生面号和行列选择，层转按预览后玩家所在面匹配客户端方向。
4. 每次调用前在客户端核对地图、棋盘阶数、位面、玩家格、移动距离和行动额度。识别节点确认卡后，通过桥接核对客户端已选格并确认进入。层转预览与目标一致后才调用客户端确认。
5. 确认进入节点后，按同一地图和落点关联移动与事件回包，再用实际事件 ID 确认事件类型。进入战斗前还会比对编队页和事件的关卡 ID。节点、奖励、战斗各保留来源与恢复阶段。移动额度和节点完成分开记录。自身动作结束后如仍有额度，会读取真实棋盘并重新选择剩余动作，计算时可复用相同规则下的未来回合数值。额度耗尽后等待实际奇点阶段。
6. 奇点行动结束、新位面加载后重新扫描，不依赖奇点动作记录。普通战斗胜利不能结束位面；奇点战胜利后仍需实际间隙、新位面或最终结算。

回生空洞和莫测漩涡按原生事件及选项 ID 执行各自目录的选择策略。事件和战斗的奖励卡、途中出现的单选奖励和满包弹窗均由桥接器读取及操作。奖励一张选唯一、两张选第一张、三张选中间。满包时保留已有直觉，放弃新直觉。

每次推进最多发出一个原生操作。取消或阻塞时保存状态。

位面序号、剩余回合、移动和层转额度、灵感进度及页面状态由桥接器读取。位面序号使用当前地图配置的 `faceIndex`。移动距离和有效额度包含客户端加成。每次读取棋盘同步取得行动额度，校验期间位面或额度变化则重新读取。

## 会话与证据

结果位于仓库 `logs/deep_dive_planned_run/<session_id>/`：

- `session.json`：位面、实际额度、扫描／地图／镜头版本、布局、待确认动作、事件上下文、收益账本及停止原因。
- `scans/`、`plans/`：每次完整扫描与相应方案。
- `operations/<action_id>/action.json`：原生目标格、旋转预览及确认依据。
- `frames/`、`report.md`：可用的起止截图及最终摘要。动作与事件写入统一日志。

`terminal_reached` 表示已经到达结算；`game_success` 表示游戏胜败，未知时为 `null`。收益账本只采用节点结束后或稳定玩家棋盘的地图灵感 HUD 进度，不按奖励点击数入账，也不把奇点战后的旧位面清空计数记作玩家拾取。

## 当前限制及后续验收

- 三至五阶的每回合模型包括一次同面移动和一次层转。读取到的移动距离为一格或两格，最多纳入四枚场上灵感。未知节点入口、无法确认的 HUD 或超出模型的移动距离和行动额度会使任务暂停。
- 节点入口和最终结算使用客户端状态。移动完成后核对实际额度，再读取新棋盘。
- 遇到无法解析的页面时，任务按当前阶段的超时停止并尝试保留截图。
- 本次新扫描无法对齐前次灵感身份时，不猜测单枚灵感的消失原因；规划使用当前自由灵感集合和已确认 HUD 收集基线。

已在三阶棋盘逐一打开四个层转预览并撤销，核对了移动到商店格的选中坐标后撤销。实际确认动作、位面切换、整局结算和取消清理仍需完整实机验收。
